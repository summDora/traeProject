# 全战略态势内容区：方案 C 双尺寸适配

> 适用页面：`src/pages/sys_page/sys_quanzhanlvetaishi/`（实验室 · 全战略态势大屏）
> 设计基准：**2880**（1920 视为同一套 UI 的压缩态）

---

## 一、锁定决策

| # | 决策 |
|---|------|
| 1 | **不做整页 `transform: scale`**（避免 1920 上下留白、文字发糊） |
| 2 | 以 **2880 为设计基准**写结构与视觉 token；1920 视为压缩态 |
| 3 | 组件只认父容器：`width/height: 100%`，**不写死 100vh**（头文件外置、方便移植） |
| 4 | 图表统一用项目已有的 **ECharts 5** |
| 5 | 首期先搭壳子 + 三栏 + 中间 Tab 舞台切换；各图可用**静态 mock**，后续再接真数据 |
| 6 | 【战略板块】内部不做复杂 DOM/流程图还原，统一用**单张切图铺满占位**（切图未到前用灰色/半透明占位块） |
| 7 | 目标环境以 **Windows 为主**（约 90% 展示机）；验收以 Windows + Chrome/Edge 为准，Mac 仅作开发预览 |
| 8 | **图表组件化**：每种图表单独成组件，props 收数据、根节点铺满父级并自管 resize |
| 9 | 【量化目标切换】完整复用三态切换（目标地图/排名列表/发布情况），封装为独立组合组件 |
| 10 | 风格主题兼容：同一套图表支持 **dark / light** 两套主题，通过 `theme` prop 切换 |

### Windows 环境约定

- 字体栈优先 Windows 常见中文字体：`"Microsoft YaHei", "PingFang SC", sans-serif`
- 滚动条、字重、发虚感以 Win 实机为准
- 避免只在 Mac 上看着合适

## 二、适配机制（方案 C 核心）

在 `QuanzhanlvetaishiContent.vue` 根节点挂 **ResizeObserver**：

```js
const DESIGN_W = 2880;
const scale = Math.min(Math.max(containerWidth / DESIGN_W, 0.67), 1);
// 1920 → ≈0.67，2880 → 1
```

将 `scale` 写入 CSS 变量 `--qzlt-s`，再派生 token：

- `--qzlt-gap`、`--qzlt-pad`
- `--qzlt-font-sm / md / lg`
- `--qzlt-radius`、`--qzlt-col-gap` 等

布局用 flex 百分比/弹性，尺寸用这些变量，**不用整页缩放**。

### 三栏线框宽度（2880 设计稿标注，不含栏间距）

| 区域 | 设计稿宽度 |
|------|-----------|
| 左栏 | 702px |
| 中栏（舞台区） | 1284px |
| 右栏 | 702px |

### 水平尺寸关系（2880 画布）

```
三栏线框：702 + 1284 + 702 = 2688px
栏间距：左右各 16px，共 32px  → gap: calc(16px * var(--qzlt-s))
剩余外边距：2880 - 2688 - 32 = 160px（对称则各约 80px，随 s 缩放）
```

### 实现要点

- 三栏按 `702 : 1284 : 702` 分配；容器 `display: flex; gap: var(--qzlt-col-gap)`
- 随 `--qzlt-s`：左/中/右视觉宽约 `702*s / 1284*s / 702*s`；1920 下 `s≈0.67` → 约 468 / 857 / 468，间距约 11px
- 中栏 `min-width: 0`，热力过密时在舞台内横滑
- 高度：`.qzlt-content` 已是 `flex: 1`（见 `styles/index.scss`）；内部三栏 `height: 100%`，左右上下两块用 flex 分高，中间舞台 `flex: 1; min-height: 0`

## 三、F11 全屏防抖约定

- 页面壳保持 `height: 100vh; overflow: hidden`（已有），避免全屏切换时滚动条出现/消失导致宽度来回跳
- `--qzlt-s` **只跟容器宽度走**；高度变化只靠 flex 填满，不因 F11 多出的纵向空间改字号比例
- ResizeObserver 覆盖多数场景；可额外监听 `fullscreenchange` / `resize` 做一次 token 与图表 resize 的兜底刷新
- **禁止用 100vw 算布局宽**（含滚动条时与 100% 不一致，进出全屏更易抖）
- 验收：窗口最大化下连续 F11 开/关数次，三栏比例与间距稳定，图表不裁切、不错位

## 四、组件拆分

### 本页布局（`sys_quanzhanlvetaishi/components/`）

| 组件 | 职责 |

| `center/PortraitView.vue` / `GoalView.vue` / `HeatmapView.vue` | 只组合筛选与图表组件，不含图表内部实现 |

### 可复用层（`src/pages/sys_page/charts/`，与业务页解耦）

**原子图表**（props: `{ data, theme }`）：

- `RadarChart.vue` — 政策画像雷达
- `ChinaMapChart.vue` — 目标地图
- `RankBarChart.vue` — 排名横向条
- `ReleaseBarChart.vue` — 发布情况柱状
- `DirectionHeatmap.vue` — 方向热力矩阵

**组合组件**（他页整段复用）：

- `GoalVizSwitcher.vue`（名称可微调）— 内含二级切换【目标地图 \| 排名列表 \| 发布情况】+ 下方舞台；`v-model/active` 控制当前态；组装 ChinaMapChart / RankBarChart / ReleaseBarChart；透传 `theme`、`data`
- 本页 `center/GoalView.vue` 只引用该组合组件（可再包一层本页筛选），**不重复实现三态切换**

### 原子图表通用约定

- 根节点 `width/height: 100%`，自管 resize
- 样式自包含，不依赖 `.qzlt-page`
- theme 用根 class（`.sys-chart--dark` / `.sys-chart--light`）+ ECharts option 内按 theme 取色板
  - **light**：白/浅灰底、深色文字、常规描边
  - **dark**：透明/深底、浅色文字、青色高亮（对齐本大屏）

页面壳 `index.vue` / 头部不改职责。

## 五、交互与视图约定

### 1. 左上政策统计

- 布局：左（若干 KPI/分类卡片）\| 右（明细列表）
- 点击左侧某一项 → 高亮该项 → 右侧列表绑定该分类下的条目与数值（mock 先按分类切换数组）
- 右侧列表条数可超过可视区域 → **必须纵向滚动**；滚动发生在列表容器内，不撑破左上卡片、不影响战略板块高度
- 关键 CSS：右侧 `.qzlt-stats-list { flex: 1; min-height: 0; overflow-y: auto }`（父级限高 + `min-height: 0`）
- Windows 下注意滚动条宽度占用，预留或美化细滚动条，避免挤乱图标与数字对齐

### 2. 中间舞台（多图切换通用）

- `CenterPanel` 只维护 `activeMainTab`（画像 / 目标 / 热力），切换组合视图
- 舞台 `.qzlt-stage`：`flex: 1; min-height: 0; overflow: hidden`
- 密度策略：
  - **疏图**（雷达、柱图、地图）：填满舞台
  - **密图**（热力）：列最小宽 + 字号下限；不够则舞台内横向滚动

### 3. 右侧外部动态

- 内容有调整、细则未定 → 本期**只做线框占位**（标题区 + 空内容区/占位块，保持 702 宽与面板样式）
- 不做日期筛选、标签圆钮、动态列表的精细还原与交互；后续定稿再补

### 4. 战略板块

- 内部不做复杂 DOM/流程图还原，统一**单张切图铺满**该区域占位
- 实现时预留 `<img>`（或背景图）位与资源路径（如 `src/asset/images/sys/`）
- 切图未到前用灰色/半透明占位块撑住布局，切图到位后只替换资源即可（勿用 HTML 拼层级）
